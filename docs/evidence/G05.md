**PARTIAL — 25/10/2026.** O fluxo normal Conectar → autorização no navegador → catálogo → escolha de escopo → consulta pessoal foi observado com a conta real. Não qualifica cenários de erro, renovação, retomada, remoção ou PR preenchido. Fonte configurada: **859b273**; nenhuma mudança de lógica ou novo build nesta passagem.

## Evidência humana e CUA

1. Usuário respondeu **“Autorizei e a lista apareceu”** após o roteiro Conectar → Copiar código e abrir GitHub → autorização pessoal. Root aguardou esse relato antes de observar o app; não leu/capturou o desafio, código, token ou navegador OAuth.
2. CUA observou no Radar **Conectado como** a identidade proprietária, **Escolha seus repositórios**, busca, **0 de 10 selecionados · 68 carregados**, checkboxes com público/privado e **Começar a acompanhar** desabilitado. Nenhum escopo antigo foi aplicado automaticamente. Nomes privados não são copiados para esta evidência.
3. Root filtrou pelo nome de um repositório público existente já exibido: permaneceu somente essa opção. Limpou o campo e a lista original reapareceu, preservando zero selecionados. Foi interação com dados reais, sem criar teste, mock ou fixture e sem escolher o escopo pelo usuário.
4. Usuário respondeu **“Escolhi e iniciei o acompanhamento”** após marcar repositórios e usar Começar a acompanhar. Root não inferiu nomes/quantidade das escolhas nem ampliou o acesso.
5. CUA observou o indicador **GitHub. Total exato: 0. Consulta recebida**. Ao abri-lo, o painel apresentou **GitHub 0**, **Nenhum item pessoal encontrado no escopo consultado** e **Consulta recebida**. Jira permaneceu desconectado. [Painel real sem itens pessoais](images/G05-github-connected-empty.png).

O valor zero é o resultado observado do Radar; não houve comparação independente com busca no GitHub nem comprovação de PRs/detalhes/relações preenchidos. Consulta vazia foi distinguida de falha pela UI. O painel não foi populado artificialmente.
